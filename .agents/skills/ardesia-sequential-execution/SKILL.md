# ardesia-sequential-execution

## Inputs
Read AGENTS.md, docs/START_HERE.md, the immutable live cursor and its adopted docs/recurring-work.md. Load the complete canonical task, referenced history/lesson and scoped AGENTS. Record actual start, current claim, source/procedure identities, environment and deadline before work.

## Procedure
Use the existing queue and tools/cycle.mjs; never wait for a Pro actor in v2. Claim with expected revision/parent, publish without force and reread before writes. Assign must preserve all canonical exit criteria; additional bounded checks are permitted. Keep the same run budget across successors. Reuse applicable source/configuration/toolchain/environment/fixture evidence; use ardesia-sequential-review for non-author review.

For release/access work read docs/release-runbook.md and e2e/README.md only when that boundary is involved. Check the authorized runtime's actual capabilities; metadata access, OIDC, three QA identities and operator/restore connections are separate. Preserve the original gate, freeze, preflight/postflight and source read-only boundary. Missing channels block that operation; no unchanged login/403 retry, credential scraping, resource duplication, bypass or inferred permission.

For closure use the adopted helper's supported completion/reconciliation flow. Runtime source never supplies task authority. Preserve immutable completion and release refs across interruptions; reconcile existing evidence before redoing product work. A proposed helper change does not become adopted by appearing in a newer branch.

## Output and errors
Return consumer/task, source and procedure refs, evidence identity/access, review context, publication state, rollback and one executable successor. WAITING_CI retains the original URL/head. A live or expired foreign claim permits read-only work and isolated proposals, not takeover. Missing review stays pending. Never reset a dirty worktree. No scheduler/model/permission changes; stop writers and close within 55 minutes of the actual start.

## Proof
Use the relevant cycle/check-operations tests plus actual Git parent/CAS observations and original CI artifacts. Synthetic transitions prove guards only; two real increments and interruption recovery require observed operational evidence. Do not turn structural PASS into product or human acceptance.

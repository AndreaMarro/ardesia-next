## Prova locale riproducibile

Usare Node 24, il lockfile e un checkout pulito della head da provare:

```sh
npm ci
npm run build
npm run preview
```

Aprire `http://127.0.0.1:4173/fisica/index.html`, scegliere un corso e «Prova il quiz». Il confronto rivela il feedback della scelta; lo svolgimento completo si apre separatamente. Le stesse pagine in `apps/web/dist/fisica/` si possono aprire da file, anche senza rete. I link di contatto esterni richiedono rete.

Con la preview ancora aperta, in un secondo terminale:

```sh
npx playwright install chromium
node tools/test-physics-demo.mjs
```

Il test demo esegue 125 confronti su 25 feedback distinti: HTTP a 390/820/1440 px, HTTP senza JavaScript e file offline senza JavaScript. Controlla contenuto, tastiera, chiusura iniziale, soluzione separata, overflow e le risorse secondo gli ambiti registrati. Produce `/tmp/ardesia-demo-browser.json` e schermate `/tmp/ardesia-demo-*.png`. Richiede la preview già avviata; non è ancora uno step della CI. Chiudere la preview prima della suite E2E, che possiede la stessa porta.

Per l’app autenticata e i test PostgreSQL seguire [provisioning server](../../packages/server/README.md) e [comandi di verifica](../../README.md#verifiche-riproducibili). Non usare dati reali: `setup-test-databases.mjs` e il runner browser preparano database loopback dedicati. La verifica completa richiede `M3_TEST_DATABASE_URL` sul database locale `_test`: eseguire `npm run verify` solo dopo quel provisioning. Per il browser, con `ARDESIA_E2E_MODE=local` e `M3_BROWSER_DATABASE_URL` configurati sul database locale `_browser`:

```sh
npm run test:e2e -- e2e/pressure-unit.spec.ts
```

Nel corso importato aprire un’unità, salvare una risposta, consultare un aiuto e salvare un altro tentativo. «Il filo dei tuoi tentativi» permette di distinguere le fotografie degli aiuti al momento del salvataggio; filtrare conserva i numeri originali e la bozza, senza scrivere nel Core. Il test controlla queste proprietà e la riapertura via API reale.

## Prove e ingegnerizzazione

Le [54 ricevute preservate](../sources/physics-2026-27/reviews-2026-11-13/README.md) includono revisioni indipendenti AI e report sintetici con le identità originarie. Il manifest ne conserva SHA256 e provenienza. I dossier editoriali mantengono ricalcoli, fonti, correzioni e ambito scientifico. Questi controlli non sostituiscono revisione umana o prova con studenti.

| Sorgente | Evidenza locale completata |
|---|---|
| `dd98a8c` | Verify 8/8, 690 unit test, 5 verifiche bundle server e 16 MCP; 4 prove browser C2/C3 sui confronti guidati |
| `e2f9236` | Verify 8/8 e 690 unit test; demo: 125 confronti sui cinque quiz, inclusi no-JS/offline; ispezione schermate |
| `d4d8456` | Verify 8/8 e 690 unit test; 2 prove pressione desktop/mobile passate, 0 skip/flaky, nessun retry; schermate della cronologia ispezionate |

I PASS della tabella appartengono a quelle sorgenti, non alla futura head. Verify viene rieseguito dopo questa documentazione; la CI della head pubblicata rimane la fonte del suo risultato completo. SHA, digest e URL della run sono riportati nella PR. Nessun PASS remoto, merge, deploy o accettazione M3 è dedotto dai test locali.

Conservati anche i fallimenti: import di test fuori confine poi corretto con l’export pubblico; selettore accessibile poi corretto; lettura transitoria ECONNRESET; letture della revisione prima della conferma degli aiuti/fase. Nell’ultimo caso due test su `5e26e6e` attendevano revisione 11 e leggevano 10 mentre il comando era pendente. Il fix `d4d8456` attende la fase confermata prima della lettura API, mantenendo valore atteso, persistenza e timeout.

La [CI precedente](https://github.com/AndreaMarro/ardesia-next/actions/runs/43387937221) durava 18m02s, di cui 14m37s per il browser, con tetto job 20 minuti. La suite aggiunge sei casi browser di laboratorio: il tetto del solo job diventa 30 minuti per eseguire l’intera suite sequenziale. Restano invariati timeout dei singoli test, un worker, retry, asserzioni, limiti di bundle, permessi e pin delle action. È una capacità prevista per il carico ampliato, non una misura del tempo della nuova CI. Il README è allineato al limite Core già vigente di 327.680 byte (ADR0023); la policy non viene aumentata. Il Core misurato nel report conservato di `5e26e6e` è 327.453 byte: margine ridotto di 227 byte.
